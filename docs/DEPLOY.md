## 결정 (2026-09-12)

| 항목 | 선택 | 이유 |
|---|---|---|
| 앱 | **Render** (무료 플랜) | 카드 등록 없이 시작 가능, 설정이 가장 단순 |
| DB | **TiDB Cloud Serverless** | MySQL 호환이라 지금 코드(JPA + MySQL 드라이버)를 그대로 쓸 수 있음 |

```
[태블릿 / 관람객]
      │ HTTPS
      ▼
[Render — Spring Boot]  ──TLS──▶  [TiDB Cloud Serverless]
```

## 배포 전 확인 항목

- [ ] `backend/Dockerfile` 작성 (또는 Render 의 Java 빌드 사용)
- [ ] DB 접속 정보를 **환경변수로 주입** — `application-local.yml` 은 gitignore 대상이라 배포 환경에 존재하지 않는다
- [ ] `application.yml` 의 `spring.profiles.active: local` 처리 — 배포에서는 다른 프로필이나 환경변수가 필요하다
- [ ] TiDB 연결 확인 (아래 주의사항)
- [ ] Render 와 TiDB 의 **지역(region)을 같은 곳으로** — 다르면 쿼리마다 왕복 지연이 붙는다
- [ ] **512MB 메모리 안에서 실제로 뜨는지** 확인
- [ ] 헬스 체크 경로를 `/api/health` 로 지정 (서버 파트에서 추가 예정, #18)
- [ ] 프론트 배포 방식 결정 — 아래 참고

## 환경변수

배포 플랫폼에만 넣고 **저장소에는 커밋하지 않는다.**

| 이름 | 설명 |
|---|---|
| `SPRING_DATASOURCE_URL` | TiDB 접속 URL (TLS 옵션 포함) |
| `SPRING_DATASOURCE_USERNAME` | TiDB 사용자 이름 |
| `SPRING_DATASOURCE_PASSWORD` | TiDB 비밀번호 |
| `SPRING_PROFILES_ACTIVE` | 배포용 프로필 (`local` 이 아닌 값) |
| `CORS_ALLOWED_ORIGINS` | 프론트 주소. 서버 파트에서 지원 예정 (#18) |

## 알아둘 것

**Render 무료 플랜은 15분 동안 요청이 없으면 잠듭니다.** 다시 깨어나는 데 수십 초가 걸립니다.
- 행사 시작 전에 한 번 접속해 미리 깨워둘 것
- 사람이 계속 이어지면 잠들지 않음
- 점심시간처럼 비는 구간이 있으면 주기적으로 호출해 두는 방법도 있음

**TiDB 는 일반 MySQL 과 다른 점이 있습니다.**
- **TLS 연결이 필수**입니다. JDBC URL 에 SSL 옵션이 필요합니다
- 사용자 이름 형식이 다릅니다 (콘솔에서 연결 문자열을 복사해 쓰는 편이 안전)
- 외래키 제약은 버전에 따라 동작이 달라, 쓰지 않는 편이 안전합니다

**프론트 배포 방식은 아직 미정입니다.**

| 방식 | 장점 | 단점 |
|---|---|---|
| 정적 호스팅 따로 | 프론트 배포가 빠름 | 주소가 달라 **CORS 설정 필요** |
| 빌드 결과를 jar 에 포함 | 같은 주소라 CORS 설정 불필요, 서버 하나만 관리 | 프론트만 고쳐도 전체 재배포 |

**무료 플랜 조건은 자주 바뀝니다.** 가입 전에 각 서비스의 공식 요금 페이지를 확인해주세요.

## 개발용 DB 와 분리

행사 기록에 개발 중 테스트 데이터가 섞이지 않도록 **개발용과 배포용 데이터베이스를 분리**하는 편이 좋습니다.

## 서버 파트가 준비하는 것 (고은우, #18)

- [ ] `GET /api/health` — 배포 헬스 체크와 서버 깨우기에 사용
- [ ] CORS 허용 오리진을 환경변수로 받도록 변경 (현재 `http://localhost:5173` 고정)

## 인터넷이 끊겼을 때

부스에서 인터넷이 끊기면 게임이 멈춥니다. 행사 당일 대비가 필요하면 노트북에서 로컬 MySQL + jar 로 돌리는 예비 경로를 미리 연습해두는 방법이 있습니다. 진행 여부는 팀에서 결정해주세요.
