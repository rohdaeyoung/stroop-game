# Figma 3종 연속 촬영 프레임 설계

## 목표

기존 카메라 프레임 4종을 제거하고 Figma 파일의 새 프레임 3종으로 교체한다. 사용자는 프레임을 선택한 뒤 촬영 버튼을 한 번만 누르며, 선택한 프레임의 사진 칸 수만큼 서로 다른 사진이 3초 간격으로 자동 촬영된다.

## 프레임과 촬영 장수

- `Photomatic (25-08)`: 좌우 사진 칸에 서로 다른 사진 2장
- `폴라로이드 대지 (흩어진 2장)`: 위·아래 사진 칸에 서로 다른 사진 2장
- `Story of Film Pro 01`: 위 1장과 아래 2칸에 서로 다른 사진 3장

프레임 선택 전에는 촬영을 시작하지 않는다. 촬영을 시작하면 매 사진마다 `3 → 2 → 1` 카운트다운을 표시하고 자동으로 셔터를 실행한다. 첫 촬영 이후에는 사용자의 추가 버튼 입력을 요구하지 않는다.

## 프런트엔드 구조

프레임별 차이를 데이터로 정의한다. 각 프레임 설정은 표시 이름, 오버레이 에셋, 미리보기 에셋, 촬영 장수와 사진 칸의 합성 좌표를 가진다. 공통 카메라 컴포넌트는 선택된 설정을 읽어 필요한 장수만큼 연속 촬영하고, 완료 후 각 이미지를 정의된 칸에 순서대로 합성한다.

촬영 중에는 현재 진행 상태를 `1/2`, `2/3`처럼 보여준다. 모든 사진이 준비된 후에만 기존의 `다시 찍기`와 `이 사진으로 할게요` 동작을 노출한다. 다시 찍기는 현재 프레임 선택을 유지하면서 촬영 결과 전체를 초기화한다.

## 이미지 합성

카메라 영상은 각 사진 칸을 빈틈없이 채우도록 `cover` 방식으로 중앙 크롭한다. 폴라로이드처럼 회전된 칸은 Figma의 위치와 회전을 그대로 적용한다. 프레임 장식은 사진 위에 그려 최종 결과 한 장에 포함한다.

최종 결과는 기존과 동일하게 JPEG 품질 0.85로 생성한다. 백엔드의 1MB 제한을 넘는 경우에 대비해 현재 출력 캔버스 크기 안에서 합성하고, 필요하면 품질만 낮춰 제한을 지킨다.

## 백엔드와 데이터 흐름

백엔드 API와 DB는 변경하지 않는다. 브라우저가 여러 장의 원본 사진을 메모리에서 합성한 후 최종 JPEG 한 장만 기존 `POST /api/photos`에 업로드한다. QR 생성과 5분 보관 흐름도 그대로 유지한다.

## 에셋 정리

기존 `basic`, `dots`, `denim`, `stamp` 프레임·마스크·미리보기 에셋과 참조 코드를 제거한다. 새 에셋은 Figma 원본에서 내려받아 저장하며 임시 원격 URL에 의존하지 않는다.

## 테스트

- 선택 가능한 프레임이 새 3종뿐인지 검증한다.
- 프레임별 촬영 장수가 각각 2장, 2장, 3장인지 검증한다.
- 촬영 버튼이 한 번만 필요하고 이후 촬영이 자동 진행되는지 검증한다.
- 각 촬영 결과가 서로 다른 사진 칸에 순서대로 합성되는지 검증한다.
- 다시 찍기가 촬영 결과와 진행 상태를 초기화하는지 검증한다.
- 최종 결과가 기존 업로드 흐름에 전달되는지 검증한다.

## 완료 조건

세 프레임 모두 선택·연속 촬영·미리보기·재촬영·확정이 가능하고, 프런트엔드 전체 테스트와 프로덕션 빌드가 통과해야 한다. 백엔드 파일과 API 명세에는 변경이 없어야 한다.
