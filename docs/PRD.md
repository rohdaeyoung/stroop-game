# PRD — 어흥! 색에 속지 마

> 이 문서는 **무엇을 왜 만드는가**를 정합니다.
> 실행 방법과 협업 규칙은 [README.md](../README.md), 게임 숫자는 [GAME_RULES.md](GAME_RULES.md),
> FE↔BE 계약은 [API.md](API.md) 를 보세요.
>
> `[확인 필요]` 는 아직 정해지지 않은 것입니다. 정해지면 표시를 지웁니다.

## 1. 한 줄 요약

색깔 단어의 **뜻과 글자 색이 다를 때 뇌가 얼마나 쉽게 속는지**(스트루프 효과)를 60초 게임으로 만든 1인용 웹 게임.

## 2. 왜 만드는가

- 규칙이 한 문장으로 설명된다 — "글자의 색을 고르세요"
- 한 판이 **60초**로 끝나 여러 사람이 짧게 돌아가며 할 수 있다
- 아는데도 자꾸 틀린다. **틀리는 모습을 옆에서 보는 것도 재미**가 된다
- 랭킹에 이름이 남아 다시 하고 싶어진다

## 3. 성공 지표 `[확인 필요]`

| 지표 | 기준 |
|---|---|
| 처음 온 사람이 설명 없이 시작하기까지 | 30초 이내 |
| 1인당 진입 ~ 랭킹 확인 | `[확인 필요]` |
| 재도전 비율 | `[확인 필요]` |
| 오류 없이 동작 | 시연 중 치명 오류 0 |

## 4. 사용자와 환경

| 항목 | 내용 |
|---|---|
| 플레이어 | 처음 보는 사람, 1명씩. 로그인 없음 |
| 입력 | 터치 우선 (태블릿), 마우스도 가능 |
| 기기 | `[확인 필요]` — 태블릿 몇 대? 노트북으로도 하나? |
| 네트워크 | 배포 서버 접속 필요 ([README 배포 계획](../README.md)) |
| 운영 방식 | `[확인 필요]` — 행사 부스에서 운영하나? 상품이 있나? |

**운영 방식이 정해져야 판단이 달라지는 것들**: 대기 화면 필요 여부, 성공/실패 기준(상품 지급 기준), 랭킹 초기화 주기.

## 5. 화면 흐름

```
[온보딩] ──▶ [게임 60초] ──▶ [결과] ──▶ [랭킹]
   │                                      │
   └──────────────── 다시 하기 ◀──────────┘
```

| 화면 | 하는 일 | 담당 |
|---|---|---|
| 온보딩 | 규칙 안내, 예시 문제, 닉네임 입력 | 최복순 |
| 게임 | 문제 출제, 타이머, 점수·콤보 | 김민서 |
| 결과 | 점수·정답 수 표시, 서버에 제출 | 이혜원 |
| 랭킹 | 상위 10명, 내 순위 | 이혜원 |

## 6. 기능 요구사항

**P0** = 없으면 게임이 성립하지 않음 / **P1** = 있어야 재미있음 / **P2** = 여유 있으면

### 온보딩 (최복순)
- P0 규칙 한 줄 설명 + 예시 문제 1개
- P0 닉네임 입력 (1~10자)
- P1 처음 틀렸을 때 "글자의 **색**을 고르세요" 재안내
- P2 대기 화면 (운영 방식 확정 후)

### 게임 엔진 (김민서)
- P0 모드 A(글자 색) / 모드 B(단어 뜻) 출제 — 단어 뜻과 글자 색은 항상 다름
- P0 질문 문구가 화면에 항상 보임
- P0 문제별 제한시간, 60초 전체 타이머
- P0 점수·콤보·속도 보너스 계산 ([GAME_RULES.md](GAME_RULES.md))
- P0 난이도 가속 (제한시간 단축, 선택지 증가)
- P0 종료 조건 3가지 (미응답 / 오답 3회 / 60초)
- P1 정답·오답 피드백 연출
- P2 효과음 (음소거 필수)

### 결과·랭킹 (이혜원)
- P0 점수, 정답/오답 수, 최대 콤보 표시
- P0 `POST /api/scores` 제출 — 중복 제출 방지, 실패해도 점수는 보여주기
- P0 상위 10명 랭킹
- P1 내 순위·백분위 표시 (`GET /api/rankings/me`)
- P1 신기록이면 강조

### 디자인 (나연)
- P0 색 토큰 — 선택지에 쓸 색 `[확인 필요: 총 몇 개?]`
- P0 터치 대상 크기, 대비 확보
- P1 정답·오답·콤보 연출 가이드

### DB·도메인 (노대영)
- P0 점수 저장, 랭킹 정렬 쿼리
- P0 배포용 설정 — `application-prod.yml`, 운영 DB 는 `ddl-auto: validate`

### 서버 (고은우)
- P0 점수 제출·랭킹 조회 API
- P0 잘못된 요청을 API 명세대로 응답 (PR #16)
- P0 `/api/health` — 배포 헬스 체크 (#18)
- P0 CORS 허용 주소를 환경변수(`CORS_ORIGIN`)로 — 프론트가 별도 주소로 배포됨 (#18)
- P1 점수 값 일관성 검증 `[#20 확정 후]`
- P1 닉네임 금칙어 필터 — 랭킹에 공개되는 값

### 배포 (노대영 · 고은우)
- P0 Render + TiDB Cloud 배포 — 구성과 체크리스트는 [README 배포 계획](../README.md)

## 7. 비기능 요구사항

- **색 가독성** — 배경 대비 확보. 노랑 계열은 흰 배경에서 잘 안 보임
- **색각 이상** — 빨강·초록 구분이 어려운 사람이 있다. 색만으로 구분되지 않게 하거나 최소한 안내 `[확인 필요]`
- **터치** — 버튼 최소 44px 이상, 더블탭 확대 방지, 연타 시 한 문제에 한 번만 입력
- **개인정보** — **닉네임만** 수집한다. 실명·연락처는 받지 않는다
- **닉네임 필터** — 공개 화면에 뜨므로 금칙어 차단 필요
- **서버 콜드 스타트** — Render 무료 플랜은 15분 무요청 시 잠들고 깨는 데 30~50초 걸린다. 결과·랭킹 화면은 로딩 문구를 정직하게 보여주고, 요청 타임아웃을 60초 이상으로 두고, 연결 실패를 "기록 없음"으로 표시하지 않는다 (README 배포 계획 참고)

## 8. 범위 밖 (하지 않는 것)

- 로그인·회원가입
- 멀티플레이, 실시간 대결
- 사진·이미지 업로드
- **점수 조작 방지** — 서버는 값의 일관성만 검증한다. 완전한 조작 차단은 목표가 아니다
- 모바일 앱 (웹만)
