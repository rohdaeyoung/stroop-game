# PRD — 어흥! 색에 속지 마

> 이 문서는 **무엇을 왜 만드는가**를 정합니다.
> 실행 방법과 협업 규칙은 [README.md](../README.md), 게임 숫자는 [GAME_RULES.md](GAME_RULES.md),
> FE↔BE 계약은 [API.md](API.md) 를 보세요.
>
> `[확인 필요]` 는 아직 정해지지 않은 것입니다. 정해지면 표시를 지웁니다.

## 1. 한 줄 요약

색깔 단어의 **뜻과 글자 색이 다를 때 뇌가 얼마나 쉽게 속는지**(스트루프 효과)를 60초 게임으로 만든 1인용 웹 게임.
게임이 끝나면 인증샷을 찍어 **QR 로 휴대폰에 받아갈 수 있다.**

## 2. 왜 만드는가

- 규칙이 한 문장으로 설명된다 — "글자의 색을 고르세요"
- 한 판이 **60초**로 끝나 여러 사람이 짧게 돌아가며 할 수 있다
- 아는데도 자꾸 틀린다. **틀리는 모습을 옆에서 보는 것도 재미**가 된다
- 랭킹에 이름이 남고, 인증샷을 가져가 부스 경험이 기억에 남는다

## 3. 성공 지표 `[확인 필요]`

| 지표 | 기준 |
|---|---|
| 처음 온 사람이 설명 없이 시작하기까지 | 30초 이내 |
| 1인당 대기화면 ~ QR 까지 | `[확인 필요]` |
| 재도전 비율 | `[확인 필요]` |
| 오류 없이 동작 | 부스 운영 중 치명 오류 0 |

## 4. 사용자와 환경

| 항목 | 내용 |

## 5. 화면 흐름

Figma 시안 기준입니다.

```
01 대기화면 → 02 두 모드 소개 → 03 안내·연습문제 → 04 카운트다운 → 05 플레이 (60초)
→ 05b 게임 종료 → 06 닉네임 입력 → 07 결과 → 08 랭킹
→ 09 인증샷 촬영 → 10 QR 발송 → 01 대기화면
                 ↘ "사진은 괜찮아요!" → 01 대기화면
```

| 화면 | 하는 일 | 담당 |
|---|---|---|
| 01 대기화면 | 화면을 터치해서 시작 | 최복순 |
| 02 두 모드 소개 | 모드 A(글자 색) / B(단어 뜻) 설명 | 최복순 |
| 03 안내·연습문제 | 예시 문제 1개, 정답·오답 피드백 | 최복순 |
| 04 카운트다운 | 3·2·1 | `[확인 필요]` |
| 05 플레이 | 문제 출제, 타이머, 점수·콤보·목숨 | 김민서 |
| 05b 게임 종료 | 종료 사유 3종 표시, 획득 점수 | 김민서 |
| 06 닉네임 입력 | 랭킹에 표시될 이름 입력 | `[확인 필요]` |
| 07 결과 | 점수·정답 개수·최고 콤보·정확도·현재 순위, 서버 제출 | 이혜원 |
| 08 랭킹 | 상위 10명, 내 순위 강조, 순위권 밖이면 내 순위 고정 카드 | 이혜원 |
| 09 인증샷 촬영 | 3초 자동 촬영, 프레임 선택 | 이혜원 |
| 10 QR 발송 | 사진 받을 QR 표시, 5분 후 만료 | 이혜원 |

## 6. 기능 요구사항

**P0** = 없으면 부스 운영이 성립하지 않음 / **P1** = 있어야 재미있음 / **P2** = 여유 있으면

### 대기화면·온보딩 (최복순)
- P0 대기화면 — 화면을 터치해서 시작
- P0 두 모드 소개 — **모드는 게임 중 매 문제 랜덤으로 바뀐다**는 것을 알려야 함 ([GAME_RULES.md](GAME_RULES.md))
- P0 연습 문제 1개 + 정답·오답 피드백
- P1 튜토리얼 강화 버전 (Figma 02b)

### 게임 엔진 (김민서)
- P0 모드 A(글자 색) 70% / 모드 B(단어 뜻) 30%, **매 문제 랜덤** — 단어 뜻과 글자 색은 항상 다름
- P0 질문 문구가 화면에 항상 보임
- P0 문제별 제한시간, 60초 전체 타이머, 목숨(오답 3회)
- P0 점수·콤보·속도 보너스 계산
- P0 난이도 가속 (제한시간 단축, 선택지 증가)
- P0 게임 종료 화면 — 종료 사유 3가지(오답 3회 / 미응답 / 60초)를 구분해 표시
- P1 정답·오답 피드백 연출 (`SPEED +250`, `MISS -50`)
- P2 효과음 (음소거 필수)

### 닉네임 입력 `[담당 확인 필요]`
- P0 **게임 종료 후** 입력
- P0 한글·영문·숫자 1~10자 — 서버와 **같은 정규식**으로 미리 검사 ([GAME_RULES.md](GAME_RULES.md) 서버 검증)

### 결과·랭킹 (이혜원)
- P0 점수, 정답 개수, 최고 콤보, **정확도** 표시
- P0 성공/실패 표시 — 10,000점 기준 ([GAME_RULES.md](GAME_RULES.md))
- P0 `POST /api/scores` 제출 — 중복 제출 방지, 실패해도 점수는 보여주기
- P0 제출 응답의 순위로 "현재 랭킹 N위" 표시
- P0 상위 10명 랭킹, 내 기록 "(나)" 강조
- P1 순위권 밖이면 **내 순위 고정 카드** (`GET /api/rankings/me`)
- P1 신기록이면 강조

### 인증샷·QR (이혜원, [#41](https://github.com/rohdaeyoung/stroop-game/issues/41))
- P1 카메라 미리보기, 3초 후 자동 촬영
- P1 프레임 4종 선택 (기본 · 땡땡이 · 데님 · 우표) + 결과 정보 합성
- P1 합성 사진 업로드(`POST /api/photos`) → 받은 토큰으로 QR 표시, 5분 만료 안내
- P1 "사진은 괜찮아요!" 로 건너뛰기, 카메라 권한 거부 시 안내

### 디자인 (나연)
- P0 색 토큰 5개 (빨강 · 파랑 · 초록 · 노랑 · 보라)
- P0 터치 대상 크기, 대비 확보
- P1 정답·오답·콤보 연출 가이드
- P1 인증샷 프레임 4종

### DB·도메인 (노대영)
- P0 점수 저장, 랭킹 정렬 쿼리 (점수 → 먼저 등록 → id)
- P0 배포용 설정 — `application-prod.yml`, 운영 DB 는 `ddl-auto: validate`

### 서버 (고은우)
- P0 점수 제출·랭킹 조회 API
- P0 잘못된 요청을 API 명세대로 응답 (#33)
- P0 점수 서버 검증 — 점수·오답·플레이시간 범위 (#32)
- P0 동점자 순위를 랭킹 목록과 같은 기준으로 계산 (#37)
- P0 닉네임 문자 규칙 — 한글·영문·숫자만 (#39)
- P0 `/api/health`, CORS 허용 주소 환경변수화 (#18)
- P1 인증샷 5분 임시 보관 API (#40)
- P2 닉네임 금칙어 필터

### 배포 (노대영 · 고은우)
- P0 Render + TiDB Cloud 배포 — 구성과 체크리스트는 [README 배포 계획](../README.md)

## 7. 비기능 요구사항

- **색 가독성** — 배경 대비 확보. 노랑 계열은 흰 배경에서 잘 안 보임
- **색각 이상** — 빨강·초록 구분이 어려운 사람이 있다. 색만으로 구분되지 않게 하거나 최소한 안내 `[확인 필요]`
- **터치** — 버튼 최소 44px 이상, 더블탭 확대 방지, 연타 시 한 문제에 한 번만 입력
- **개인정보**
  - 닉네임 — 랭킹에 공개된다. 실명·연락처는 받지 않는다
  - **인증샷(얼굴 사진)** — **서버 메모리에 5분만 보관 후 자동 삭제**한다. DB 에 저장하지 않고 랭킹에도 노출하지 않는다. 촬영 전에 이 내용을 안내한다
- **카메라** — 브라우저 카메라는 HTTPS 에서만 동작한다 (Render 는 HTTPS)
- **서버 콜드 스타트** — Render 무료 플랜은 15분 무요청 시 잠들고 깨는 데 30~50초 걸린다. 결과·랭킹 화면은 로딩 문구를 정직하게 보여주고, 요청 타임아웃을 60초 이상으로 두고, 연결 실패를 "기록 없음"으로 표시하지 않는다 (README 배포 계획 참고)

## 8. 범위 밖 (하지 않는 것)

- 로그인·회원가입
- 멀티플레이, 실시간 대결
- **사진 영구 저장, 랭킹에 사진 노출** — 인증샷은 5분 임시 보관만 한다
- **점수 조작 방지** — 서버는 값의 일관성만 검증한다. 완전한 조작 차단은 목표가 아니다
- 모바일 앱 (웹만)
